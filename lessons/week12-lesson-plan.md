## Learning outcome

Given a small project change and a prepared tool trace, a student can explain
an expected result and failure case, distinguish a model proposal from an
executed call, locate the host's permission decision and check the actual
result before saying what happened.

## Worked trace and answers

Person: "add 3 and 4". Model suggests `add` with `{"a": 3, "b": 4}`. Host
checks that `add` is on its allowlist, then dispatches through an MCP client
to a server exposing only the pure addition tool. The function returns 7;
the server passes that result back. The host reports 7 only after inspecting
the result. This is a **prepared trace**, not a report from a live MCP session.

For `{"a": 3}` or `{"a": "3", "b": 4}`, stop and report invalid input; the
actual validation layer depends on the chosen runtime. For a tool error or
missing result, report failure rather than inventing 7. An overwrite proposal
is out of host scope: no call is sent and there is no file-write tool. Approval
of future side effects needs a person to see the specific target and action.
